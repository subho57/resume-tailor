One clear example is the Steampipe Model Context Protocol (MCP) server I built at Turbot HQ. Before this, there was no way for LLM agents to get standardized, real-time access to the cloud and security data Steampipe already collected — every integration would have meant a one-off, hand-rolled connection. I identified this as a gap, then designed and built the MCP server end to end in Python: defining the protocol-compliant interface, wiring it to Steampipe's existing data layer, and handling authentication and query translation so any MCP-compatible LLM client could plug in with zero custom integration work.

My role was full ownership, prototype through production: I made the architecture calls, wrote the implementation myself, and took it from "does this even work" to something teammates and downstream tools now rely on for real-time cloud/security data access. It's a good example of the kind of 0→1 work I enjoy — spotting where a manual or ad hoc process should instead be a clean, reusable capability, then building and shipping it myself rather than just proposing it.

I've since applied the same pattern to a RAG-based agent (embeddings-backed vector store, deployed on AWS Lambda) and a multi-agent workflow on the OpenAI Agents SDK — in both cases owning the idea, the build, and the path to production.
